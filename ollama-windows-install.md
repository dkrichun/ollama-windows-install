# Ollama для Windows — Установка, Обновление и Удаление

Комплект скриптов для развёртывания и обслуживания [Ollama](https://ollama.com) на Windows в виде службы через [NSSM](https://nssm.cc). Оптимизирован под **NVIDIA RTX 4060 (8 ГБ VRAM)**, но работает на любом железе с подстройкой INI.

## Состав комплекта

| Файл | Назначение |
|---|---|
| `ollama-windows-install.ini` | Единый конфиг (пути, сеть, модели, производительность) |
| `ollama-windows-install.ps1` | Установка, обновление, переустановка и логирование |
| `ollama-windows-uninstall.ps1` | Удаление службы и очистка |
| `ollama-windows-install.md` | Этот файл (документация) |

Все четыре файла должны лежать в одной папке — например, `D:\AI\Ollama\install`.

## Основные возможности

1. **Безопасная папка `install`.** Скрипты и лог-файл хранятся в `D:\AI\Ollama\install`. При обновлении или переустановке эта папка (включая подпапку `OllamaTM`) **никогда не удаляется**.

2. **Защищённые папки внутри `OllamaDir`.** Следующие каталоги хранятся внутри `D:\AI\Ollama` и не затрагиваются при обновлении:
   - `install\` — скрипты и лог
   - `logs\` — логи службы (с ротацией по `LogRetentionDays`)
   - `Downloads\` — кэш дистрибутивов `ollama_<версия>\` и `nssm_<версия>\`
   - `Backup\` — бэкапы бинарников при обновлении
   - `Models\` — скачанные модели
   - `.ollama\` — профиль и ключи (id_ed25519)

   Скачанный архив NSSM (`Downloads\nssm_<версия>\NSSM_vX.zip`) **сохраняется** и переиспользуется при следующих запусках.

3. **Умное обновление и переустановка.**
   - Скрипт определяет текущую версию и показывает меню со всеми стабильными релизами.
   - Текущая версия помечена как `(переустановка)` — её можно выбрать для полной переустановки (например, если файлы повреждены).
   - **Выбор версии и подтверждение происходят в самом начале** — до остановки службы и создания бэкапов. Если нажать `s` в меню, служба продолжит работать без изменений.

4. **План действий.** Перед началом работы скрипт показывает сводку (текущая версия → целевая, режим, нужен ли бэкап) и просит финальное подтверждение `Продолжить? [Y/n]`.

5. **Описание службы.** В NSSM автоматически прописывается официальное описание:
   > Ollama is the most popular way to build with open models. Access the latest open models with complete privacy locally or in the cloud. Your prompts are never stored or trained on.

6. **Очистка `OllamaTM.exe`.** Перед обновлением/удалением скрипт принудительно завершает процессы `OllamaTM`, `ollama app`, `ollama`, `ollama_llama_server`, чтобы избежать ошибки «Access denied».

7. **Безопасные права (SID).** Используется `*S-1-5-18` (SYSTEM) и `*S-1-5-32-544` (Administrators) для `icacls`, что гарантирует работу на любой локализации Windows (русская, английская, немецкая и т.д.).

8. **Логирование.** Все действия записываются в `ollama-windows-install.log` (в папке со скриптом).

9. **Ротация логов.** Скрипт очищает файлы в `LogsDir` старше `LogRetentionDays` (по умолчанию 7 дней). Управляется через INI.

10. **Автообновление (`-Upgrade`).** Параметр позволяет запускать скрипт в Планировщике Windows для автоматической установки последней версии без интерактивных запросов.

11. **Диагностика.** При невозможности запустить службу скрипт выводит `ExitCode`, последние строки логов и результат `nssm dump`, а также пытается запустить `ollama.exe serve` напрямую для выявления причины.

## Быстрый старт

1. Отредактируйте `ollama-windows-install.ini` (проверьте `FirewallSubnet` и пути).
2. Запустите `.\ollama-windows-install.ps1`.
3. Если Ollama уже установлена:
   - Вы увидите текущую версию.
   - Меню покажет список стабильных версий с пометкой `(переустановка)` на текущей.
   - Нажмите **`s`**, чтобы отменить — служба не будет остановлена.
   - Или выберите нужную версию (новую для обновления, текущую для переустановки).
4. Скрипт покажет «План действий» и спросит финальное `Продолжить? [Y/n]`.
5. Дождитесь завершения установки и проверки API.

## Параметры запуска `ollama-windows-install.ps1`

| Параметр | Описание |
|---|---|
| `-Force` | Не задавать интерактивных вопросов (не показывать меню версий, брать `OllamaVersion` из INI или `latest`, не спрашивать про переустановку). |
| `-ForceDownload` | Принудительно перекачать архивы, даже если они есть в кэше `Downloads`. Также сбрасывает кэш списка релизов. |
| `-Upgrade` | Режим автообновления: включает `-Force`, ставит `OllamaVersion=latest`, отключает интерактивный выбор моделей. Предназначен для планировщика. |
| `-NoPause` | Не ждать нажатия Enter в конце (для CI/CD и Планировщика). |
| `-ConfigPath` | Путь к нестандартному INI-файлу. |

## Автообновление (Планировщик Windows)

Чтобы настроить ежедневное автообновление до последней версии:

1. Откройте **Планировщик заданий** (Task Scheduler).
2. Создайте задачу с триггером (например, ежедневно в 3:00).
3. В действии укажите:
   - **Программа**: `powershell.exe`
   - **Аргументы**: `-NoProfile -ExecutionPolicy Bypass -File "D:\AI\Ollama\install\ollama-windows-install.ps1" -Upgrade -NoPause`
4. Включите опцию **«Выполнять с наивысшими правами»** (Run with highest privileges).
5. (Опционально) Настройте условие «Запускать задачу, только если компьютер подключен к сети».

Лог работы будет писаться в `D:\AI\Ollama\install\ollama-windows-install.log`.

## Сценарии

| Хочу... | Действие |
|---|---|
| Обновиться с v0.40.10 → v0.40.12 | Запустить скрипт → выбрать `[1] v0.40.12` → подтвердить |
| Даунгрейд с v0.40.12 → v0.40.10 | Запустить скрипт → выбрать нужную версию |
| **Переустановить текущую** (например, файлы повреждены) | Запустить скрипт → выбрать версию с пометкой `(переустановка)` → подтвердить |
| Отменить обновление | Запустить скрипт → нажать `s` в меню (служба не тронута) |
| Тихо переустановить (без вопросов) | `-Force` + `OllamaVersion=latest` в INI |
| Первичная установка | Запустить на «чистой» машине — меню без пометки текущей |
| Автообновление по расписанию | `-Upgrade -NoPause` в планировщике |

## Удаление

```powershell
# Удалить службу, сохранив модели, бэкапы и архивы
.\ollama-windows-uninstall.ps1

# Полная очистка (включая модели, архивы и бэкапы)
.\ollama-windows-uninstall.ps1 -PurgeProfile -PurgeModels -PurgeOllama -PurgeLogs -PurgeDownloads -PurgeBackup -Force -NoPause
```

**Флаги удаления:**

| Флаг | Что удаляет |
|---|---|
| `-PurgeProfile` | `D:\AI\Ollama\.ollama` (профиль с ключом id_ed25519) |
| `-PurgeModels` | `D:\AI\Ollama\Models` (скачанные модели) |
| `-PurgeOllama` | Бинарники в `D:\AI\Ollama` (папки `install`, `logs`, `Downloads`, `Backup`, `Models`, `.ollama` сохраняются) |
| `-PurgeLogs` | `D:\AI\Ollama\logs` |
| `-PurgeDownloads` | `D:\AI\Ollama\Downloads` (включая подпапки версий) |
| `-PurgeBackup` | `D:\AI\Ollama\Backup` |

**Без флагов** удаляется только служба, правило брандмауэра, PATH и переменные окружения. Все каталоги остаются на месте.

## Конфигурация INI (краткая справка)

Все параметры подробно описаны в самом файле `ollama-windows-install.ini`. Ключевые:

| Секция | Параметр | Назначение |
|---|---|---|
| `[paths]` | `OllamaDir` | Куда ставится Ollama |
| `[paths]` | `ModelsDir` | Куда скачиваются модели |
| `[paths]` | `DownloadsDir` | Кэш дистрибутивов |
| `[paths]` | `BackupDir` | Бэкапы при обновлении |
| `[paths]` | `NssmDir` | Куда распаковывается NSSM |
| `[paths]` | `LogsDir` | Логи службы (пусто = `OllamaDir\logs`) |
| `[service]` | `LogRetentionDays` | Сколько дней хранить логи (0 = не удалять) |
| `[service]` | `AddToPath` | Добавить `OllamaDir` в `PATH` |
| `[network]` | `Host` | `0.0.0.0` (сеть) или `127.0.0.1` (локально) |
| `[network]` | `FirewallSubnet` | Подсеть для правила брандмауэра |
| `[downloads]` | `OllamaVersion` | `ask`, `latest` или конкретная (например `0.40.10`) |
| `[downloads]` | `KeepDownloads` | Оставлять архивы после распаковки |
| `[models]` | `Models` | Список моделей для скачивания (через запятую) |
| `[performance]` | `FlashAttention` | Обязателен при `KvCacheType != f16` |
| `[performance]` | `KvCacheType` | `f16`, `q8_0` или `q4_0` |

## Диагностика

Если служба не запускается, скрипт автоматически:

1. Выведет текущий `ExitCode` службы.
2. Прочитает последние строки логов `ollama.err.log` и `ollama.out.log` (включая копии из бэкапа).
3. Выполнит `nssm dump Ollama` (с корректной OEM-кодировкой для русских сообщений).
4. Запустит `ollama.exe serve` напрямую на 5 секунд с теми же env-переменными, чтобы показать ошибку в STDOUT/STDERR.

### Типичные проблемы

| Симптом | Решение |
|---|---|
| **Порт занят** | `Get-NetTCPConnection -LocalPort 11434 -State Listen` покажет PID |
| **Нет прав** | Убедитесь, что скрипт запущен от имени Администратора |
| **Битый архив** | Удалите `Downloads\ollama_<версия>` и запустите с `-ForceDownload` |
| **Служба падает сразу после старта** | Смотрите `ollama.err.log`, чаще всего — права на `.ollama` или битый бинарник |
| **Логи растут бесконечно** | Проверьте `LogRetentionDays` в INI (по умолчанию 7) |

## Проверка работы

```powershell
# Статус службы
Get-Service Ollama

# Описание службы (должно быть официальное)
(Get-CimInstance Win32_Service -Filter "Name='Ollama'").Description

# API локально
Invoke-RestMethod http://127.0.0.1:11434/api/tags

# Какие модели в памяти и где (GPU/CPU)
ollama ps

# Список скачанных моделей
ollama list
```

## Безопасность

- **Ollama не имеет встроенной аутентификации.** Ограничивайте `FirewallSubnet` и не выставляйте `Host=0.0.0.0` в публичную сеть. Для недоверенных сегментов — reverse proxy с TLS и Basic Auth (Caddy, Nginx).
- **`-PurgeProfile` удаляет `id_ed25519`.** Это ключ, которым Ollama подписывает запросы к реестру моделей. Без него он пересоздастся, но если привязывали ключ к чему-то ещё — сохраните его.
- **Права Full Control выдаются только на `OllamaDir`, `ModelsDir` и `.ollama`.** Остальные папки системы не затрагиваются.
